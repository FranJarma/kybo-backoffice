# Ventas Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans inline. Steps use checkbox syntax.

**Goal:** POS online con cuentas de mesa, delivery y cobros auditables.
**Architecture:** Esquema Drizzle normalizado, servicios transaccionales, API acotada para personal y componentes Next/Shadcn con recuperación de envíos.
**Tech Stack:** Next 16.3.6, TS 6, Drizzle, PostgreSQL/PGlite, React, Tailwind, Shadcn.
**Spec:** docs/superpowers/specs/2026-09-25-ventas.md

## Global Constraints

- Entrega local; integración externa aplazada.
- No reserva ni descuenta inventario. No publica comandas en cocina.
- Importes ARS exactos a dos decimales; fechas comerciales en Salta.
- Mantener acceso administrativo restringido y encabezados alineados.

## Review Focus

- Reintento de pago después del cierre debe devolver el resultado, sin nuevo cobro: Task 1 prueba repetición tras revisión cambiada.
- Cambio de carta entre selección y confirmación debe requerir revisión: Task 1 prueba precio concurrente y ausente.
- Dos cuentas de mesa / pagos simultáneos no deben duplicar ocupación ni exceder total: Task 1 revisiones, restricciones SQL y análisis de bloqueos; Neon multiconexión aplazado.
- Personal no debe recibir costos ni datos comerciales sensibles mediante API o SSR: Tasks 1/2 pruebas de acceso.
- Respuesta perdida y navegación no deben ofrecer una nueva venta mientras queda una incierta: Task 2 prueba reintento tras recarga.
