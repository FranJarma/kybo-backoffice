# Pantallas de compras e inventario — Task 3

Se incorporaron `/purchases` y `/inventory`, navegación, y componentes de recepción/pagos, saldos, lotes y movimientos. Recepción manual de hasta 30 renglones con búsqueda de catálogo (incluidos resultados fuera de los primeros 100), revisión y conversión exacta a unidad base con formato argentino; se envían revisiones de catálogo para detectar cambios posteriores. Compras muestra detalle histórico y pagos parciales, sin presentar costos nulos como cero. Inventario separa físico/utilizable, costo unitario con seis decimales, lotes FEFO, movimientos y paginación independiente; ingreso, merma, conteo y bloqueo piden motivo.

Cada escritura persiste en `sessionStorage` el URL relativo permitido, payload exacto y requestId, por usuario y tipo, antes del primer POST. Si no se puede guardar, no se envía. Ante respuesta incierta, recarga conserva un aviso y reintento manual del mismo envío; no se reenvía automáticamente. Una respuesta 401/403/429 conserva la clave para recuperación tras reingreso. Tras éxito se elimina la entrada; errores HTTP definitivos liberan edición. El detalle del pago recuperado corresponde a la recepción devuelta por el servidor. Se limpian borradores de pago al cambiar de recepción o iniciar otra.

Verificación: `npx tsc --noEmit` y ESLint focal de UI y prueba E2E pasan. La suite completa de Playwright tuvo 10/11 aprobadas en `/tmp/kybo-stock-e2e-final.log`; su única falla fue un localizador de prueba ambiguo para «Lotes» (también coincidía «Stock y lotes»). Se corrigió a coincidencia exacta y el recorrido correspondiente pasó en `/tmp/kybo-stock-mobile-final.log` (1/1). La regresión reforzada del borrador de pago pasó en `/tmp/kybo-stock-draft-final.log` (1/1). Por tanto, los 11 escenarios pasaron con la corrección focal, aunque no se repitió la suite completa por tercera vez. El servidor gestionado terminó en cada ejecución.
